### 🔴 Kritik kusur: DTO sözleşmesi bozuk

Backend **camelCase** döner, mobil DTO'lar `@SerialName` ile **snake_case** bekler.

Kanıt (`guestStore.listByWedding` çıktısı, gerçek PGlite):
```
GUEST_KEYS = ["id","weddingId","name","phone","side","inviteStatus","rsvp","note","deletedAt"]
```

Mobil `GuestDto` ise şöyle:
```kotlin
@SerialName("inviteStatus") val inviteStatus: String   // ← camelCase bekliyor, DOĞRU
```
ama `WeddingDto`:
```kotlin
@SerialName("couple_names") val coupleNames: String    // ← snake_case bekliyor, YANLIŞ
@SerialName("wedding_date") val weddingDate: String?   // ← YANLIŞ
```

Backend `listByUser` camelCase döndürüyor (`coupleNames`, `weddingDate`, `venueName`…). Sonuç: `coupleNames` alanı **boş gelir**, düğün adı ekranda görünmez. `ExpenseDto`/`BudgetSummaryDto` da aynı hatayı taşır.

**Bu, uygulamanın gerçek API'ye karşı çalışmadığı anlamına gelir.** Aşama 6.5'in ilk işi budur.

## 4. Veri katmanı

### 4.1 DTO düzeltmesi (KRİTİK — ilk iş)

Tüm `@SerialName` snake_case → camelCase. Backend gerçeği:
```kotlin
@Serializable data class WeddingDto(
    val id: String,
    val coupleNames: String,        // @SerialName gereksiz
    val weddingDate: String? = null,
    val venueName: String? = null,
    ...
)
```

**Doğrulama:** her DTO için gerçek backend yanıtıyla karşılaştıran test.

### 4.2 Repository genişletme

| Metot | Uç |
|---|---|
| `refreshToken` | `POST /auth/refresh` |
| `getWedding` / `updateWedding` | `GET/PATCH /weddings/:id` |
| `createWedding` | `POST /weddings` |
| `updateExpense` / `deleteExpense` | `PATCH/DELETE` |
| `getExpense` | `GET /expenses/:id` |
| `updateGuest` | `PATCH /guests/:id` |
| `createGuestsBulk` | `POST /guests/bulk` |
| `createInvitation` | `POST /guests/:id/invitation` |
| `setGuestRsvp` | `PATCH /guests/:id/rsvp` |
| `updateTask` / `deleteTask` | `PATCH/DELETE` |
| `createHelper` / `revokeHelper` | `POST /helpers`, `POST /helpers/:id/revoke` |
| `createInvite` (CO_OWNER) | `POST /weddings/:id/invites` |

### 4.3 Token yönetimi

- `TokenStore` genişletme: refresh token da sakla
- `ApiClient` 401 alınca otomatik refresh + isteği tekrar dene
- Refresh de başarısızsa oturumu kapat

### 4.4 Offline-aware (spec §6b)

v1: **server-first, okuma önbelleği**. Yazma çevrimdışı engellenir (açık mesaj).
- Son başarılı yanıt `multiplatform-settings`'ta JSON olarak
- Çevrimdışı: son veri + "çevrimdışısın" bandı
- Yazma denemesi: "İnternet bağlantısı gerekli" hatası
